## 🏗️ Архитектура и структура

### Основные компоненты

#### Главный компонент
- **`Inventory.tsx`** (768 строк) - Главный оркестратор, управляет всей логикой инвентаризации
  - Управление состоянием навигации
  - Интеграция всех подкомпонентов
  - Обработка WebSocket событий
  - Управление модальными окнами

#### Компоненты отображения
- **`CategoryGrid.tsx`** (688 строк) - Сетка категорий с прогрессом заполнения
  - Отображение всех категорий
  - Индикатор прогресса заполнения
  - Аватары активных пользователей
  - Сортировка (незаполненные сверху)

- **`ItemList.tsx`** (531 строка) - Список товаров в категории
  - Отображение товаров с статусами
  - Поддержка поиска и подсветки
  - Долгое нажатие для удаления
  - Индикатор редактирования

- **`ItemEdit.tsx`** (955 строк) - Детальный экран редактирования товара
  - Редактирование сырья (raw)
  - Редактирование полуфабриката (semifinished)
  - Валидация агрессивных изменений
  - Модальное окно заметок

- **`ItemHistory.tsx`** - История изменений товара
  - Фильтрация по датам
  - Анимации загрузки
  - Модальное окно с полной историей

#### UI компоненты
- **`Header.tsx`** (227 строк) - Заголовок с прогрессом
  - Анимированный прогресс-бар
  - Автоматическое сворачивание/разворачивание
  - Уведомления

- **`Footer.tsx`** (665 строк) - Нижняя панель навигации
  - Кнопки навигации (Назад, Домой)
  - Кнопка поиска
  - Кнопка QR-сканера
  - Кнопка активных пользователей
  - Кнопка завершения инвентаризации

#### Модальные окна
- **`OutOfStockConfirmModal.tsx`** - Подтверждение "Нет в наличии"
- **`AggressiveChangeModal.tsx`** - Подтверждение больших изменений
- **`DeleteConfirmationModal.tsx`** - Подтверждение удаления
- **`InventoryCompleteDialog.tsx`** - Диалог завершения инвентаризации
- **`TemplateChangesModal.tsx`** - Изменения шаблона
- **`QrScannerModal.tsx`** - QR-сканер
- **`ActiveUsersDrawer.tsx`** - Панель активных пользователей

#### Поиск
- **`SearchResultsDropdown.tsx`** (1068 строк) - Выпадающий список результатов
- **`InventorySearch.tsx`** (385 строк) - Компонент поиска
- **`SearchBar.tsx`** (219 строк) - Строка поиска

### Хуки (Custom Hooks)

- **`useInventoryLoader.ts`** - Загрузка данных с прогрессом
  - Загрузка списка чатов
  - Загрузка инвентаря конкретного чата

## 📊 Структура данных

### Inventory (Инвентарь)

```typescript
type Inventory = {
  [category: string]: {
    [itemId: string]: InventoryItem
  }
}
```

### InventoryItem (Товар)

```typescript
interface InventoryItem {
  raw?: {
    quantity: number          // Количество сырья
    filled: boolean           // Заполнено ли
    isOutOfStock: boolean    // Нет в наличии
    notes?: string           // Заметки
  }
  semifinished?: {
    quantity: number          // Количество полуфабриката
    filled: boolean           // Заполнено ли
    notes?: string           // Заметки
  }
}
```

### InventoryData (Данные инвентаря)

```typescript
interface InventoryData {
  chat_id: string
  chat_title: string
  inventory: Inventory
  metadata: InventoryMetadata
  admins?: string[]
  members?: string[]
}
```

### InventoryMetadata (Метаданные)

```typescript
interface InventoryMetadata {
  progress: number           // Прогресс заполнения (0-100)
  lastUpdated: string        // ISO дата последнего обновления
  chat_id: string
  lastTemplateUpdate?: {
    viewed: boolean
    timestamp: string
    changes: {
      added: string[]        // Добавленные товары
      removed: string[]      // Удаленные товары
      added_count: number
      removed_count: number
    }
  }
}
```

### HistoryRecord (Запись истории)

```typescript
interface HistoryRecord {
  id: string
  chat_id: string
  category: string
  item_name: string
  type: 'raw' | 'semifinished'
  old_quantity: number | null
  new_quantity: number | null
  timestamp: string          // ISO дата
  user_id?: number
  user_name?: string
}
```

### SearchResult (Результат поиска)

```typescript
interface SearchResult {
  category: string
  itemId: string
  item: InventoryItem
  matches: {
    field: string           // 'name' | 'description'
    value: string
  }[]
}
```

## 🌐 API Endpoints

### Получение данных

**GET `/v1/inventory/template`**
- Получить шаблон структуры инвентаря
- Возвращает: `Record<string, any>`

**GET `/v1/inventory/{chatId}`**
- Получить инвентарь для конкретного чата
- Возвращает: `InventoryData`

**GET `/v1/inventory/history/{chatId}`**
- Получить историю изменений по товару
- Query params: `category`, `item_name`
- Возвращает: `InventoryHistoryItem[]`

**GET `/groups/chats`**
- Получить список чатов пользователя
- Query params: `user_id`, `group_type`
- Возвращает: `ChatItem[]`

### Обновление данных

**POST `/v1/inventory/{chatId}`**
- Обновить инвентарь для чата
- Body: `InventoryUpdatePayload`
- Возвращает: `InventoryData`

**POST `/v1/inventory/{chatId}/items`**
- Добавить новый товар в инвентарь
- Body: `{ category, item_name, has_semifinished }`
- Возвращает: `any`

**POST `/v1/inventory/{chatId}/request-item`**
- Отправить запрос на добавление товара через бота
- Body: `{ category, item_name, has_semifinished }`
- Возвращает: `any`

### Удаление

**DELETE `/v1/inventory/{chatId}/items`**
- Удалить товар из инвентаря
- Query params: `category`, `item_name`
- Возвращает: `any`

### Дополнительные операции

**POST `/v1/inventory/{chatId}/excel`**
- Триггер генерации Excel-отчета
- Файл появится в чате Telegram
- Возвращает: `{ status, message, chat_id, file_path? }`

**POST `/v1/inventory/{chatId}/reset`**
- Сбросить инвентарь чата (очистить всё)
- Возвращает: `{ message: string }`

**POST `/v1/inventory/{chatId}/sync-template`**
- Синхронизировать инвентарь чата с актуальным шаблоном
- Возвращает: отчет об изменениях

**POST `/v1/inventory/{chatId}/mark-template-changes-viewed`**
- Отметить изменения шаблона как просмотренные
- Возвращает: `any`

## 🔌 WebSocket события

### События от сервера

**`inventory_updated`**
```typescript
{
  type: 'inventory_updated'
  chat_id: string
  metadata: InventoryMetadata
  item_id?: string
  category?: string
  item?: InventoryItem
}
```
- Обновление товара или всего инвентаря
- Может содержать конкретный товар или только метаданные

**`inventory_reset`**
```typescript
{
  type: 'inventory_reset'
  chat_id: string
  metadata: InventoryMetadata
}
```
- Сброс инвентаря
- Обновляет только метаданные

**`template_updated`**
```typescript
{
  type: 'template_updated'
  timestamp: string
  summary: {
    total_items: number
    new_items: number
    removed_items: number
    inventory_template_updated: boolean
    excel_template_updated: boolean
  }
  details: {
    new_items_list: string[]
    removed_items_list: string[]
  }
}
```
- Глобальное обновление шаблона
- Триггерит автоматическую синхронизацию

**`category_focus_update`**
```typescript
{
  chat_id: string
  category: string
  focusing: boolean
  user_info: {
    userId: string
    first_name: string
    photo_url?: string
  }
}
```
- Пользователь вошел/вышел из категории
- Обновляет аватары на категориях

**`item_editing_update`**
```typescript
{
  chat_id: string
  category: string
  item_id: string
  editing: boolean
  user_info: {
    userId: string
    first_name: string
    photo_url?: string
  }
}
```
- Пользователь начал/закончил редактирование товара
- Показывает индикатор редактирования

**`room_users_list`**
```typescript
{
  room: string
  users: Array<{
    userId: string
    first_name: string
    current_category?: string
  }>
}
```

## 🎯 Ключевые паттерны

### 1. Feature-based структура

Все компоненты, хуки, store и services находятся в папке `features/Inventory`:

```
features/Inventory/
├── components/          # Переиспользуемые компоненты
├── hooks/              # Custom hooks
├── store/              # Redux slice, selectors, thunks
├── services/           # API слой
├── pages/              # Страницы
└── *.tsx              # Основные компоненты
```

### 2. Custom Hooks для логики

Вся бизнес-логика вынесена в переиспользуемые хуки:
- `useInventoryLoader` - загрузка данных
- `useInventoryNavigation` - навигация
- `useInventorySearch` - поиск
- `useInventoryView` - управление view
- `useInventoryWebSocketSync` - WebSocket синхронизация

### 3. Redux для состояния

Централизованное управление состоянием через Redux:
- `inventorySlice` - основной slice
- `inventorySelectors` - селекторы для данных
- `inventoryThunks` - асинхронные действия

### 4. WebSocket для реал-тайм

Синхронизация между пользователями через WebSocket:
- Подписка на события в хуке
- Обработка через Redux actions
- Автоматическая перезагрузка при переподключении

### 5. Мемоизация для оптимизации

Использование `useCallback` и `useMemo` для оптимизации:
- Мемоизация функций обработчиков
- Мемоизация вычисляемых значений
- Предотвращение лишних перерисовок

### 6. Композиция компонентов

Разделение на мелкие переиспользуемые компоненты:
- Каждый компонент отвечает за одну задачу
- Легко тестировать и поддерживать
- Возможность переиспользования

## 🪝 Хуки детально

### useInventoryLoader

**Назначение:** Загрузка данных инвентаря с прогрессом

**Параметры:**
- `chatId?: string` - ID чата
- `currentUserId: number | null` - ID пользователя
- `role: string | null` - Роль пользователя

**Возвращает:**
- `isLoading: boolean` - флаг загрузки
- `error: string | null` - ошибка
- `loadInventoryData: () => Promise<void>` - функция перезагрузки
- `loadingProgress: number` - прогресс (0-100%)

**Логика:**
- Если есть `chatId` - загружает инвентарь чата
- Если нет `chatId` - загружает список чатов
- Обновляет прогресс каждые 500ms
- Обрабатывает ошибки

### useInventoryNavigation

**Назначение:** Управление навигацией по инвентарю

**Параметры:**
- `initialCategory?: string | null`
- `initialItem?: string | null`
- `onNavigate?: (category, item) => void`

**Возвращает:**
- `selectedCategory: string | null`
- `selectedItem: string | null`
- `handleCategorySelect: (category) => void`
- `handleItemSelect: (itemId) => void`
- `handleBack: () => void`
- `setNavigation: (category, item) => void`

**Логика:**
- Управляет состоянием выбранной категории и товара
- Сбрасывает товар при выборе категории
- Навигация назад: товар → категория → список категорий

### useInventorySearch

**Назначение:** Поиск по инвентарю с историей

**Параметры:**
- `inventory: Inventory | undefined`
- `onSelectResult?: (category, itemId) => void`

**Возвращает:**
- `searchQuery: string`
- `isSearching: boolean`
- `searchResults: SearchResult[]`
- `isSearchFocused: boolean`
- `searchHistory: string[]`
- `handleSearch: (query) => void`
- `handleClearSearch: () => void`
- `handleSearchFocusChange: (isFocused) => void`
- `handleSearchResultSelect: (category, itemId) => void`
- `handleHistoryItemSelect: (query) => void`

**Логика:**
- Поиск по названию и описанию товаров
- Минимальная длина запроса: 2 символа
- Задержка поиска: 300ms
- История сохраняется в localStorage (до 5 записей)

### useInventoryView

**Назначение:** Управление отображением текущего view

**Параметры:**
- `selectedCategory: string | null`
- `selectedItem: string | null`
- `inventory: Inventory`
- `renderCategories: () => JSX.Element`
- `renderItems: (category) => JSX.Element`
- `renderItemDetail: (category, itemId) => JSX.Element`
- `searchActive: boolean`
- `isLoading?: boolean`

**Возвращает:**
- `currentView: () => JSX.Element` - что рендерить
- `categories: () => string[]` - список категорий
- `categoryItems: () => Record<string, InventoryItem>` - товары категории
- `currentItem: () => InventoryItem | null` - текущий товар
- `hasValidInventory: () => boolean` - валидность данных

**Логика:**
- Определяет текущий view на основе выбранной категории/товара
- Мемоизирует функции рендеринга
- Проверяет валидность данных

### useInventoryWebSocketSync

**Назначение:** Синхронизация через WebSocket

**Возвращает:**
- `templateChanges: TemplateChanges | null`
- `isChangesModalOpen: boolean`
- `closeChangesModal: () => void`
- `checkForUnviewedTemplateChanges: (chatId, metadata?) => void`

**Логика:**
- Подписывается на WebSocket события:
  - `inventory_updated`
  - `inventory_reset`
  - `template_updated`
- Обрабатывает обновления через Redux actions
- Автоматическая синхронизация при переподключении
- Проверка непросмотренных изменений шаблона
- Показ модального окна с изменениями

## 📝 Заметки для миграции

### Что нужно адаптировать для нативного приложения:

1. **Навигация:**
   - Вместо React Router использовать React Navigation
   - 3 уровня: Categories → Items → ItemDetail

2. **WebSocket:**
   - Использовать нативную библиотеку WebSocket
   - Адаптировать обработку событий

3. **Анимации:**
   - Вместо Framer Motion использовать React Native Reanimated
   - Адаптировать анимации для нативной платформы

4. **Стили:**
   - Вместо CSS Modules использовать StyleSheet или styled-components
   - Адаптировать под мобильные размеры экранов

5. **Хранение:**
   - Вместо localStorage использовать AsyncStorage
   - Адаптировать сохранение истории поиска

6. **QR-сканер:**
   - Использовать нативную библиотеку для сканирования QR
   - Адаптировать под iOS/Android

7. **Клавиатура:**
   - Использовать Keyboard API для управления клавиатурой
   - Адаптировать логику скрытия футера

8. **Гесты:**
   - Использовать нативные обработчики жестов
   - Адаптировать долгое нажатие и свайпы
