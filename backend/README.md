# Система настроек доступа к сменам

## Обзор

Система настроек доступа к сменам предоставляет гибкие возможности для управления доступом курьеров к записи на смены. Она позволяет настраивать периоды доступа, дни недели, время, ограничения для отдельных пользователей и другие параметры.

## Компоненты системы

### 1. Хранение данных
- Настройки хранятся в JSON-файле `data/shift_access_settings.json`
- Структура настроек соответствует интерфейсу `AccessSettings` на фронтенде

### 2. Сервис доступа
- `AccessSettingsService` в `services/access_settings_service.py` обеспечивает работу с настройками
- Расчет доступных дат происходит на основе настроек
- Проверка доступности дат учитывает персональные ограничения пользователей

### 3. API эндпоинты
- `GET /api/shifts/access-settings` - получение текущих настроек доступа
- `POST /api/shifts/access-settings` - обновление настроек доступа
- `GET /api/shifts/available-dates` - получение списка доступных дат
- `GET /api/shifts/available-dates/<date>` - проверка доступности конкретной даты

### 4. WebSocket события
- `access_settings_update` - отправка обновленных настроек клиентам
- `check_dates_availability` - проверка доступности дат в реальном времени

### 5. Планировщик
- Задача `apply_access_settings` применяет настройки к сменам по расписанию
- Эндпоинт `/apply-access-settings` позволяет применить настройки вручную

## Структура настроек

```json
{
  "allowMultipleShifts": false,     // Разрешить запись на несколько смен
  "autoApprove": false,             // Автоматическое подтверждение записи
  "allowSameDay": false,            // Разрешить запись на текущий день
  
  "registrationStartDay": 4,        // День начала регистрации (0-6, воскресенье-суббота)
  "registrationStartHour": 12,      // Час начала регистрации (0-23)
  "registrationStartMinute": 0,     // Минуты начала регистрации (0-59)
  
  "offsetType": "weeks",            // Тип смещения (days/weeks/none)
  "offsetAmount": 1,                // Величина смещения
  "periodLength": 7,                // Длительность периода доступа (дни)
  
  "isAlwaysActive": true,           // Правило активно постоянно
  "activeStartDate": "",            // Дата начала активности правила
  "activeEndDate": "",              // Дата окончания активности правила
  
  "daysAhead": 14,                  // Дней вперед (устаревшее)
  "enabledDates": [],               // Список разрешенных дат (YYYY-MM-DD)
  "restrictedUsers": [],            // Список ID пользователей с ограничениями
  
  "lastUpdated": "2023-03-27T19:17:01.962191"  // Время последнего обновления
}
```

## Алгоритм расчета доступных дат

1. Проверка ограничений для пользователя
2. Проверка активности правила и периода действия
3. Определение дня недели и времени для открытия регистрации
4. Проверка, открыта ли регистрация на данный момент
5. Расчет смещения от дня регистрации (в днях или неделях)
6. Формирование списка дат на основе длительности периода
7. Добавление специальных дат из настроек

## Интеграция с фронтендом

Фронтенд использует API для получения настроек доступа и проверки доступности дат. Компонент календаря и форма записи на смену учитывают эти настройки при отображении доступных дат и обработке запросов на запись.
