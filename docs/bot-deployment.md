# Развертывание ботов

## Архитектура

Система поддерживает три типа ботов:

1. **Основной бот** (`BOT_TYPE=main`) - для авторизации пользователей
2. **Один бот компании** (`BOT_TYPE=company`) - для работы одного бота компании
3. **Все боты компаний** (`BOT_TYPE=companies`) - автоматически загружает и запускает все активные боты компаний из БД

## Конфигурация Docker Compose

### Основной бот (`bot-main`)
- **BOT_TYPE**: `main`
- **BOT_TOKEN**: токен основного бота (обязателен)
- **Порт**: 8003
- **Назначение**: авторизация пользователей через `/start auth`

### Все боты компаний (`bot-companies`)
- **BOT_TYPE**: `companies`
- **COMPANY_BOT_ID**: не требуется (игнорируется)
- **Порт**: 8004
- **Назначение**: автоматически загружает все активные боты компаний из БД и запускает их все в одном контейнере

## Как это работает

### Режим `companies`
1. При старте контейнера `bot-companies`:
   - Загружает все активные боты из таблицы `company_bots` (WHERE `is_active = true`)
   - Создает отдельный `Application` для каждого бота
   - Регистрирует все обработчики для каждого бота
   - Запускает все боты параллельно через `asyncio.create_task`

2. При добавлении нового бота компании:
   - Добавьте запись в таблицу `company_bots` с `is_active = true`
   - Перезапустите контейнер `bot-companies`: `docker-compose restart bot-companies`

3. При деактивации бота:
   - Установите `is_active = false` в таблице `company_bots`
   - Перезапустите контейнер `bot-companies`

## Преимущества

- ✅ **Масштабируемость**: один контейнер для всех ботов компаний (независимо от количества)
- ✅ **Автоматизация**: новые боты автоматически подхватываются при перезапуске
- ✅ **Эффективность**: меньше ресурсов, чем отдельные контейнеры
- ✅ **Простота управления**: один контейнер для всех ботов компаний

## Запуск

```bash
# Запустить все боты
docker-compose up -d bot-main bot-companies

# Проверить логи
docker-compose logs -f bot-companies

# Перезапустить после добавления нового бота
docker-compose restart bot-companies
```
