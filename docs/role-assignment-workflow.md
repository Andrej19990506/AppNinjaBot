# Процесс привязки ролей к группам

## Варианты привязки

### 1. **Автоматически через бота** (при добавлении бота в группу)

**Сценарий:**
- Администратор добавляет бота компании в новую группу
- Бот автоматически определяет, что это новая группа
- Бот отправляет сообщение администратору с предложением выбрать роль

**Процесс:**
```
1. Бот добавлен в группу "Продавцы Банк Бир"
2. Бот проверяет: есть ли уже привязка для этой группы?
3. Если нет → бот отправляет сообщение:
   
   "👋 Привет! Я бот компании Банк Бир.
   
   Выберите роль для этой группы:
   
   [Повар] [Курьер] [Продавец] [Отдел закупа]
   
   Или настройте роль через админ-панель."
   
3. Администратор нажимает кнопку → роль привязывается
4. Бот сохраняет привязку в БД через API
```

**Права доступа:**
- Только администраторы/создатели группы могут выбирать роль через бота

**Преимущества:**
- Быстро и удобно
- Не требует доступа к UI
- Работает прямо в Telegram

---

### 2. **Через UI админ-панели** (веб-интерфейс)

**Сценарий:**
- Администратор компании заходит в админ-панель
- Видит список всех групп компании
- Может настроить роли, функции, уведомления

**Процесс:**
```
1. Администратор открывает админ-панель
2. Переходит в раздел "Управление группами"
3. Видит список:
   
   Группа "Повара Ниндзя Пицца"
   ├─ Роль: Повар
   ├─ Функции: Инвентаризация, Закупки
   ├─ Тип: Рабочая группа
   └─ [Изменить] [Настроить уведомления]
   
   Группа "Начальство Банк Бир"
   ├─ Роль: Начальство
   ├─ Функции: Уведомления
   ├─ Тип: Только уведомления
   └─ [Изменить] [Настроить уведомления]

4. Нажимает "Изменить" → выбирает роль из списка
5. Настраивает функции и уведомления
```

**Права доступа:**
- **Супер-администратор** (создатель бота компании):
  - Может создавать/редактировать/удалять роли
  - Может привязывать группы к ролям
  - Может настраивать функции для ролей
  - Может настраивать уведомления
  
- **Администратор группы** (administrator/creator в Telegram):
  - Может изменять роль своей группы
  - Может настраивать уведомления для своей группы
  - НЕ может создавать новые роли
  - НЕ может изменять роли других групп

**Преимущества:**
- Полный контроль над настройками
- Визуальное управление
- Настройка уведомлений в одном месте

---

### 3. **Через API** (для автоматизации/интеграций)

**Сценарий:**
- Интеграция с внешними системами
- Массовое добавление групп
- Автоматизация процессов

**Процесс:**
```python
# Пример API запроса
POST /v1/group-role-mappings
{
  "group_id": -1001234567890,
  "company_role_id": 1,
  "is_working_group": true
}
```

**Права доступа:**
- Требуется авторизация через JWT
- Проверка прав администратора группы или супер-администратора компании

---

## Иерархия прав доступа

### Уровень 1: Супер-администратор компании
**Кто:** Создатель бота компании (первый администратор)

**Может:**
- ✅ Создавать/редактировать/удалять роли компании
- ✅ Привязывать/отвязывать группы к ролям
- ✅ Настраивать функции для ролей
- ✅ Настраивать уведомления для любых групп
- ✅ Управлять всеми группами компании

**Не может:**
- ❌ Управлять группами других компаний

---

### Уровень 2: Администратор группы
**Кто:** Пользователь с ролью `administrator` или `creator` в Telegram группе

**Может:**
- ✅ Изменять роль своей группы (из списка существующих ролей)
- ✅ Настраивать уведомления для своей группы
- ✅ Видеть настройки своей группы

**Не может:**
- ❌ Создавать новые роли
- ❌ Изменять роли других групп
- ❌ Настраивать функции для ролей

---

### Уровень 3: Обычный пользователь
**Кто:** Обычный участник группы

**Может:**
- ✅ Видеть роль своей группы
- ✅ Видеть доступные функции

**Не может:**
- ❌ Изменять настройки группы
- ❌ Управлять ролями

---

## Процесс создания ролей

### Вариант A: Через UI (рекомендуется)

```
1. Супер-администратор заходит в админ-панель
2. Переходит в "Управление ролями"
3. Нажимает "Создать роль"
4. Заполняет форму:
   - Название: "Продавец"
   - Код: "seller"
   - Иконка: 🏪
   - Цвет: #9C27B0
5. Выбирает функции:
   ☑ Инвентаризация
   ☐ Смены
   ☐ Закупки
   ☑ Уведомления
6. Сохраняет
```

### Вариант B: Через API

```python
POST /v1/company-roles
{
  "company_bot_id": 2,
  "role_name": "Продавец",
  "role_code": "seller",
  "icon": "store",
  "color": "#9C27B0"
}

# Затем привязываем функции
POST /v1/role-feature-mappings
{
  "company_role_id": 5,
  "bot_feature_id": 1,  // Инвентаризация
  "is_enabled": true
}
```

## Процесс привязки группы к роли

### Сценарий 1: Новая группа (бот только что добавлен)

```
1. Бот добавлен в группу "Продавцы Банк Бир"
2. Бот отправляет сообщение администратору:
   
   "👋 Привет! Я бот компании Банк Бир.
   
   Выберите роль для этой группы:
   
   [Продавец] [Начальство] [Другое...]
   
   Или настройте через админ-панель: [ссылка]"
   
3. Администратор нажимает "Продавец"
4. Бот создает привязку через API:
   POST /v1/group-role-mappings
   {
     "group_id": -1001234567891,
     "company_role_id": 5,  // Продавец
     "is_working_group": true
   }
5. Бот подтверждает:
   "✅ Группа настроена как 'Продавец'
   
   Доступные функции:
   • Инвентаризация
   • Уведомления"
```

### Сценарий 2: Изменение роли существующей группы

```
1. Администратор заходит в админ-панель
2. Находит группу "Продавцы Банк Бир"
3. Нажимает "Изменить роль"
4. Выбирает новую роль из списка
5. Сохраняет
6. Система обновляет привязку
7. Бот отправляет уведомление в группу (опционально):
   "ℹ️ Роль группы изменена на 'Продавец'"
```

## Настройка уведомлений

### Через UI

```
1. Администратор заходит в админ-панель
2. Выбирает группу "Продавцы Банк Бир"
3. Нажимает "Настроить уведомления"
4. Выбирает функцию "Инвентаризация"
5. Добавляет группы для уведомлений:
   - ☑ Начальство Банк Бир
   - ☐ Бухгалтерия Банк Бир
6. Сохраняет
```

### Через API

```python
POST /v1/group-feature-notifications
{
  "bot_feature_id": 1,  // Инвентаризация
  "working_group_id": -1001234567891,  // Продавцы
  "notification_group_id": -1001234567892,  // Начальство
  "notification_type": "excel"
}
```

## Безопасность

### Проверки при создании/изменении роли

1. **Проверка прав:**
   - Супер-администратор может создавать роли для своей компании
   - Администратор группы может только выбирать из существующих ролей

2. **Проверка уникальности:**
   - `role_code` должен быть уникальным в рамках компании
   - Группа может иметь только одну роль

3. **Валидация:**
   - `role_code` должен быть валидным (латинские буквы, цифры, подчеркивания)
   - `role_name` обязателен
   - `company_bot_id` должен существовать

### Проверки при привязке группы

1. **Проверка прав:**
   - Супер-администратор может привязывать любые группы своей компании
   - Администратор группы может привязывать только свою группу

2. **Проверка существования:**
   - Группа должна существовать
   - Роль должна существовать и принадлежать той же компании

3. **Проверка бота:**
   - Группа должна быть связана с ботом компании (через `CompanyBot.group_id` или через проверку, что бот работает в этой группе)

## UI Компоненты (для будущей реализации)

### Страница "Управление ролями"
- Список всех ролей компании
- Кнопка "Создать роль"
- Для каждой роли: редактировать, удалить, просмотреть группы

### Страница "Управление группами"
- Список всех групп компании
- Для каждой группы:
  - Текущая роль
  - Тип (рабочая/уведомления)
  - Доступные функции
  - Кнопка "Изменить роль"
  - Кнопка "Настроить уведомления"

### Модальное окно "Выбор роли"
- Список доступных ролей
- Фильтр по функциям
- Предпросмотр функций роли

### Страница "Настройка уведомлений"
- Выбор функции
- Список рабочих групп
- Список групп для уведомлений
- Добавление/удаление уведомлений
